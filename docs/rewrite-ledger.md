# Rewrite ledger

**Status:** Working document for the core rewrite. Delete it, together with the rewrite line in [AGENTS.md](../AGENTS.md), when the rewrite is done, as the [roadmap](roadmap.md) defines it. A ledger in which every row is covered or dropped stays until then.

The prototype is kept at the git tag `prototype-final`. Its tests are the behavior specification for the rewrite. The rewrite does not port them. It writes new tests against the new API that examine the same conditions.

## Rules

- Each prototype test has one row. Remove a prototype test only in the same change that sets its row to _covered_ or _dropped_, or as the next rule permits.
- A slice can remove a prototype test together with the code that the test needs, when the slice removes or breaks that code. The row stays `pending`. The test stays readable at `prototype-final`.
- When parts of one test belong to different slices, split the row. Each part gets its own row in its slice, marked _(split)_.
- _Covered_: list the new tests that examine the same conditions. Test names can change. The conditions cannot.
- _Dropped_: name the ADR that removes or changes the behavior. If a test shows that an accepted ADR is wrong, stop and write a superseding ADR.
- When a new test differs from the prototype behavior because of an ADR, write the old and new behavior in the row.
- Write new tests as black-box tests through the public API. A white-box test is permitted only for a unit without a public surface. Give the reason in the row.
- `internal/safelog` is not part of the rewrite and has no rows.

The headings give the planned slice for each test (see the [roadmap](roadmap.md)). A row can move to a different slice when the work shows a better fit.

Status values: `pending`, `covered`, `dropped`.

Changes from the prototype behavior:

- `TestForwardingTrustAndHopByHopHeaders`. Old: the gateway removed only `Forwarded`, `X-Forwarded-For`, `-Host`, `-Proto`, and `X-Real-IP`. Other identity headers, such as `X-Forwarded-Port` and `True-Client-IP`, reached the upstream, and `Alt-Svc` reached the client. New: the gateway removes all identity headers and the configured managed headers before middleware runs, removes their names from `Connection`, and removes `Alt-Svc` and hop-by-hop fields from responses, informational responses, and trailers (ADR-0012, R4 and R7). Middleware must not change the request that it gets, as `http.Handler` requires; the gateway does not change the caller's request.
- `TestUpstreamTransportPolicy`. Old: the bounded transport was example code in `cmd/gateway`, with `MaxConnsPerHost` 64. A gateway without a configured transport used `http.DefaultTransport`, with the environment proxy and transparent compression. New: `NewTransport` is the default transport of every gateway. `MaxConnsPerHost` is 0 (no limit), because a limit makes requests wait for the pool with no bound except the client context. Admission (slice 5) limits concurrency. Compression is off, and `New` rejects an `*http.Transport` with compression (ADR-0012).
- `TestInvalidRoute`. Old: errors contained the route prefix. New: errors wrap `ErrInvalidConfiguration`, give the location only, and report all problems together. `New` calls no middleware function when the structure of the configuration is not valid.
- `TestTLSHandshakeTimeout`. The prototype test examined the upstream transport of `cmd/gateway`, although the row was first planned for the server. `TestTransportTLSHandshakeTimeout` examines the same condition with `NewTransport`.
- `TestResponseHeaderTimeoutCancelsUpstream` and `TestRequestBodyStreamsBeforeClientEOF` are split. The completion part and the admission part are rows in slices 2 and 5.

Changes from the prototype behavior:

- Registration and outcome. Old: `Config.Extensions []any`, hook methods `OnRequest`, `OnBeforeUpstream`, `OnUpstreamResponse`, and `OnComplete`, and `Outcome{Duration, Err, Aborted}`. New: `Config.Hooks Hooks` with independent typed lists of `RouteMatchedHook` (ADR-0031 replaces RequestReceived), `BeforeUpstreamHook`, `UpstreamResponseHook`, and `RequestCompletedHook`, all in execution order. `Config.HeaderOwners []HeaderOwner` holds managed-header declarations separately (ADR-0030). Completion gets `Completion`: start, duration, route, selected upstream, the first failure with its phase, the rejection reason, and the abort fact. Construction errors wrap `ErrInvalidConfiguration` and give the phase and index for hooks, or the header-owner index, without configuration values. The old runtime check for unrelated provider values is dropped: typed phase lists reject them at compile time (ADR-0030). Nil values, typed nil receivers, nil adapters, and invalid header declarations still fail at startup.

Completion also runs for secure-default rejections, with a reason code and no request content (ADR-0018).
- `TestHookErrorsStopPhaseAndHideInternalDetails`. Old: 500 for a request-hook error, 502 for outbound and response hooks; `HTTPError` set the status and message. After the hooks, the core restores the hop-by-hop fields, removes generated framing fields, and fails with 500 for an invalid header name or value.
- `TestOutboundTransportFailureClosesBodyWithoutDelegating` is a white-box test. Through the gateway, `ReverseProxy` gives the transport a body wrapper whose `Close` has no visible effect, so only a direct call of the private transport wrapper shows that it closes the body.

- `TestRequestTagExtension`. Slice 1 removed the `requesttag` extension. The new test uses an extension that is defined in the test.
- Selector failures (slice-1 test `gateway_test.go:TestCustomUpstreamSelector`). Old: 502. New: 500 (ADR-0017).
- Outbound header check (slice-1 behavior, `hooks_test.go:TestOutboundHeaderCheckDoesNotDependOnHooks`). New: the core checks the outbound headers and trailer names for each request, also without hooks, and a failure is 500 in `PhaseBeforeUpstream` (ADR-0019). Traffic with such headers from middleware now fails.
- Upstream hosts (slice-1 tests `gateway_test.go:TestStaticUpstreamAcceptsValidURL` and `gateway_test.go:TestStaticUpstreamRejectsInvalidURL`, extended). Old: any host. New: only a host that the transport sends without changes, so `OutboundRequest.Host` is the wire value; an internationalized name needs its Punycode form, and IPv6 zones are rejected (ADR-0019).

Changes from the prototype behavior:

- Rejections. Old: a hook returned `*HTTPError{StatusCode, Message}`; the body was the free-text message, and completion got the error. New: a hook returns `(*Rejection, error)`, and a `Rejection` has `Status`, `Reason`, and `Header`; an error always wins over a rejection (ADR-0022). The 4xx/5xx rule is kept: an invalid rejection, also one with an invalid reason or header, gives 500, stops the later hooks of the phase, and gives a `Failure` in the phase of the hook that wraps `ErrInvalidRejection` and contains no value of the rejection. Only processing hooks can return a rejection.
- Hook signatures (all slice-2 tests with processing hooks). Old: the processing hooks returned `error`. New: they return `(*Rejection, error)`; the tests return `nil, err` where they returned `err` (ADR-0022).
- Error bodies (all slice-1 and slice-2 tests that checked a body). Old: the status text, such as `Bad Gateway\n`, as `text/plain`. New: `{"type":"about:blank","title":"Bad Gateway","status":502}` as `application/problem+json`, with `"reason"` for rejections, also for the secure defaults and `no_route` (ADR-0022).
- `TestProxyErrorRemainsAvailableWithoutAutomaticLogging`. The URL in the test error has no user information, because the linter rejects a password in a URL literal; the credential text is in the wrapped error, and the test still checks that no output contains it.

Old: 502 for a round-trip timeout or cancellation, 500 for a hook that returned the cancellation. New: 504 for a typed round-trip timeout; 499 when the error reports the cancellation and the client context is canceled, in each processing stage (ADR-0023).

Changes from the prototype behavior:

- Body limit. Old: the opt-in middleware `bodylimit.New(n)` panicked for a negative limit, sent a text 413 for a declared length over the limit as a middleware response, and kept the `*http.MaxBytesError` of a streaming overflow in `Outcome.Err`. New: the body limit is a secure default of 10 MiB (`DefaultBodyLimit`), set with the `BodyLimit` value type on `Config` and `Route`, where `MaxBodyBytes(0)` permits only empty bodies and `NoBodyLimit()` disables the limit. `New` returns an error for a negative limit. The gateway matches once before body readers and selects one fixed effective route limit. A declared length over that limit is a 413 rejection with `body_too_large` before processing middleware. Shared readers use the route limit, including a limit larger than the gateway default. The old provisional-limit and consumed-before-match behaviors are dropped by ADR-0031. A streaming overflow is a failure with an error that wraps `ErrRequestBodyTooLarge` and `*http.MaxBytesError`; it gets 413 only when the body limit of the request found the overflow (ADR-0025). The body is `problem+json` (ADR-0022).
- Admission. Old: the opt-in middleware `admission.New(n)` panicked for a limit that is not positive, sent a text 503, and recorded no reason; its position in the middleware list set what it covered. New: `NewAdmissionBudget` returns an error for such a limit, and `New` rejects a budget that it did not make and the same budget for the gateway and a route. The gateway budget is taken before matching and shared middleware; a route budget follows the route body-length check and precedes RouteMatched hooks and buffering. The 503 has `admission_saturated` and a `problem+json` body. Completion observes saturation, but processing middleware does not run for earlier rejections (ADR-0031 supersedes the coverage of ADR-0025).
- `TestCancellationDuringPoolAcquisitionReleasesAdmissionSlot`. Old: 502 for the canceled pool wait. New: 499, because the error reports the cancellation and the client context is canceled (ADR-0023).
- Egress. Old: the opt-in package `egress.New(template, Config)` returned `ErrDenied`, used a 30s dial budget for a nil dialer, and silently did not copy the proxy, dial, and protocol callbacks of the template. New: `NewEgressTransport(template, EgressPolicy)` in the core returns errors that wrap `ErrInvalidConfiguration` and `ErrEgressDenied`. A nil template uses the settings of `NewTransport`, and a nil dialer the 3s timeout of `NewTransport`. A template with a proxy, `DialTLSContext`, a non-empty `TLSNextProto`, proxy-connect settings, a TLS `ServerName`, or transparent compression is rejected. `DialContext` is replaced; the deprecated `Dial` and `DialTLS` fields and registered protocols are not copied. The resolver is the `EgressResolver` interface of the policy, not the resolver of the dialer. A failed dial returns a `*DialError` with the attempts of that dial (ADR-0025). A denial is 502 with a `problem+json` body.
- `TestCancellationAndConnectionBudget`. Old: the test called the dialer directly with a canceled context. New: `http.Transport` dials with a context that request cancellation does not cancel, so the test checks through the public API that a canceled request returns the cancellation (499) and no `DialError`, that `CloseIdleConnections` stops the dial, and that the lookup budget, the dial budget, and the absolute deadline of the dialer give a `DialError` with `context.DeadlineExceeded` and 504.
- `TestExistingPoolIsNotSharedAndSettingsArePreserved` and `TestUnconfiguredDialAuthorityIsDenied` are white-box tests. The base transport of an `EgressTransport` has no public surface. The authority check of the dialer is a second line behind the origin check of `RoundTrip`, so no request through the public API reaches it with an authority that is not allowed.
- Fragments in the request target (slice-1 test `inbound_test.go:TestSecureDefaultsRejectBeforeMiddleware`, extended). Old: an unescaped `#` after `?` in an origin-form target stayed in the raw query, because `url.ParseRequestURI` does not split it there, and the core forwarded it; an unescaped `#` in the path got 400 with `invalid_path`. New: an unescaped `#` anywhere in the target gets 400 with `invalid_request_target`; a `%23` in the path still gets `invalid_path` (ADR-0026, amended 2026-11-06). The reason code of a `#` in the path changes.
- Request trailers (slice-1 test `inbound_test.go:TestRequestTrailersCannotCarryRemovedHeaders`, extended). Old: the core checked only the declared trailer names. `ReverseProxy` copied the trailer map before the end of the body, so no trailer value reached the upstream, and middleware saw undeclared late names when the core stripped nothing. New: the request of the middleware has its own trailer map; at a successful end of the body the core checks all trailers, rejects an invalid name in reject mode with `ErrInvalidTrailerName` (400) or removes it in drop mode, removes identity, managed, hop-by-hop, and the RFC 9110 section 6.5.1 fields (framing, `Host`, authentication, cookies, request modifiers, content format), and publishes the other values to the middleware request and the outbound request (ADR-0027).
- `TestDialDeadlineDoesNotLimitResponseStreaming` waits until the dial deadline passed, as the prototype test did. There is no event that shows that a deadline did not stop a stream.
- Response-body read failures (slice-2 tests `TestStreamingFailureAbortsAndCompletes` and `TestClientCancellationReachesUpstreamAndCompletion`, and slice-3 test `TestStreamFailureDiagnosticOmitsDetails`). Old: an abort during the response copy had no `Failure`. New: a read error other than `io.EOF` after the response hooks reaches completion in `PhaseResponseBody`, with the original cause. The committed response, abort behavior, middleware observations, and source-only diagnostics stay unchanged (ADR-0028).

## Route-first follow-up (ADR-0031)

These changes deliberately replace ordering behavior, not the completion guarantee:

| --- | --- | --- |
| Shared middleware processes route misses and early body/admission rejection | `TestSharedMiddlewareSkipsRouteMiss`, `TestCompletionOnEarlyExits`, `TestRouteMatchedSkipsDeclaredRejection`, access-log early-outcome tests | Processing is route-first; completion remains outside it |
| `TestBodyOverLimitAtRouteMatchIsRejected` and provisional overflow cannot be undone | `TestSharedBodyReadsUseMatchedLimit`, `TestSharedReaderUsesEffectiveRouteLimit` | One effective limit, selected before permitted reads |
| Body reads before routing count toward a later replacement limit | `TestSharedReadCountsTowardFixedRouteLimit`, `TestSharedAndTransportReadsWithinFixedLimit` | Shared reads count toward the already fixed limit |
| Mutable-limit internal tests | `TestOverflowStaysFinal`; `TestReadWithLimitBelowBytesRead` is dropped | No provisional limit or setter exists |
| RequestReceived observes shared-middleware context/state before routing | `TestLifecycleContextAndOrder`, `TestCompletionOnEarlyExits`, `TestRouteMatchedSkipsDeclaredRejection` | Restricted RouteMatched checks follow admission and precede body processing |

The complete check includes lint, workflow checks, shuffled tests, all-package race tests, vet, and a module-tidy diff. Zizmor ran offline, so network-dependent audits were not available.

Regression probes temporarily restored unsafe behavior and were then reverted. The first verification of ADR-0031 recorded these probes:

- With outbound GetBody restored, both retry tests failed: HTTP/1.1 forwarded twice and returned 200, and HTTP/2 forwarded twice and returned 204.
- With the gateway limit imposed as a ceiling, `TestSharedReaderUsesEffectiveRouteLimit` failed for larger configured and default-inherited route limits and for a disabled route limit.

- With an empty body of unknown length changed to length zero, the empty case of `TestBufferingDoesNotEnableTransportReplayRetries` and of `TestBufferedForwardDeclaresStoredSize` failed.
- Without the exemption for requests without a body, `TestBufferedRequestWithoutBodySkipsBuffering` failed. With a full-limit reservation for declared lengths, `TestBufferedDeclaredLengthReservesDeclaredBytes` failed.

- With data after a reservation discarded, `TestBufferFillRejectsDataAfterReservation` failed.
- Without the forwarded length, the `http2=true` cases `unread cursor` and `replay after read` of `TestBufferedForwardDeclaresStoredSize` failed, so the rule also holds for inbound HTTP/2 without a declared length.

Changes from the prototype behavior:

- Access-log API. Old: `accesslog.New(Config{Report, TraceID}) *Extension`, `RequestIDFromContext`, and a `Record` with `Outcome`, `Upstream` (an origin string), and a `Result` classification. New: `accesslog.New(Config{Sink, TraceID}) (*Recorder, error)`, which returns `ErrNoSink` for a nil sink, also a typed nil value; the `Sink` interface with `SinkFunc`; `Recorder.RequestID(rc)` instead of a context value; and a `Record` with the unchanged `Completion` and no `Result`, because the rejection reason and the failure phase keep the distinctions (ADR-0009, ADR-0029). The registered value is not called `Extension`, because the glossary keeps that word for the package. `Record` implements `slog.LogValuer` and gives only the safe fields.
- `TestMissingMiddlewareAndStandaloneUse`. Old: without its middleware, the extension reported no record. New: it reports a record with `Observed == false` and only the execution facts, because completion observes rejections by the secure defaults, which occur before any middleware, so that access logs see them (ADR-0018). Outside a gateway the behavior does not change: the middleware sets no `X-Request-ID` and adds no value to the context, and no record is reported.
- `TestLocalResponsesAndGatewayFailures`. Old: `HTTPError` rejections, a 502 for a response-hook error, a `Result` for each case, and the upstream status 503 also when a response hook rejected. New: typed rejections with a reason code (ADR-0022); 500 for hook failures with their phase (ADR-0017); `ErrInvalidRejection` for an invalid rejection; `no_route` for a routing miss (ADR-0018); and `UpstreamStatus` 0 when an inner response hook rejects or fails, because the recorder is last in the `UpstreamResponse` list and its hook then does not run (ADR-0030). `TestRecordsCoreProtectionRejections` adds `body_too_large` and `admission_saturated` (ADR-0025).
- `TestStreamingReadFailureKeepsPartialHTTPObservations`. Old: the abort had no error in `Outcome.Err`. New: completion has a `Failure` in `PhaseResponseBody` with `io.ErrUnexpectedEOF` (ADR-0028). The status and the partial byte count stay. The test runs through `Server` on HTTP/1.1 and HTTP/2.
- Request ID. Old: the middleware cloned the request to replace the client value of `X-Request-ID`. New: the recorder declares `X-Request-ID` as a managed header, so the core removes the client value, and its `BeforeUpstream` hook sets the generated ID in the outbound request. No clone of the request is necessary.
- `TestResponseStatusesAndRequestID`. Old: the response writer set the request ID again at the final status, because `ReverseProxy` cleared the headers after a 1xx response. New: the core restores the headers of middleware after a 1xx response and removes them from the 1xx response (ADR-0019). The writer removes the ID from a 1xx response and sets it again after it, so an upstream 1xx value does not reach the client. The recorder also removes upstream values from declared and undeclared trailers. The tests check 103 responses without the ID, a final response with one ID, and trailers without the ID, on HTTP/1.1 and HTTP/2 (ADR-0029). The prototype did not remove upstream IDs from 1xx responses or trailers.
- `TestProtocolUpgradePreservesHijacking`. New: the test runs through `Server` and also checks that `Shutdown` still closes the upgraded connection of the gateway when the recorder wraps the response writer (ADR-0024).
- Response-writer tests. Old: white-box tests of the private capture type. New: black-box tests that give a writer to `Gateway.ServeHTTP` and examine the writer that middleware after the recorder gets.
- Outbound signing. Old: `outboundsign.New() *Extension`, `WithKey(secret) Middleware`, and 502 with a plain-text body for every failure. New: `outboundsign.New() *Signer` and `WithKey(key) (Middleware, error)`, which returns `ErrShortKey` before serving for a key shorter than `MinKeySize` (32 bytes, RFC 2104, section 3). A missing key returns `ErrNoKey` and gives 500, because the failure is in an extension (ADR-0017). A done context gives 499 when the client is gone and 500 otherwise (ADR-0023). The body is `problem+json` (ADR-0022). The prototype counted body reads in a later hook; `OutboundRequest` has no body, so the new test sends the body only after the upstream got the headers. It checks the negotiated client HTTP version and the signature on the wire for HTTP and HTTPS upstreams. The extension is a demonstration, not an authentication protocol.
- Completion log. Old: `cmd/gateway` used `internal/safelog.ErrorKind` and a `result` allowlist. New: `examples/gateway` uses only the public API, with its own error classification and allowlists for the method, the core rejection reasons, and the failure phase. The program fails at startup when `WithKey` rejects the signing key.

New tests without a prototype row: `extensions/accesslog/accesslog_test.go:TestSinkPanicIsDropped` (a recovered sink panic does not stop other completion hooks or replace the original panic, ADR-0029), `extensions/accesslog/accesslog_test.go:TestNewValidatesAndCopiesConfig`, `extensions/accesslog/config_test.go:TestNewRejectsNilSinks` and `extensions/accesslog/config_test.go:TestNewAcceptsNonNilSinks` (nil and non-nil sinks in each supported form), `extensions/accesslog/lifecycle_test.go:TestRepeatedMiddlewareKeepsOneObservation`, `extensions/accesslog/lifecycle_test.go:TestRequestIDEndsAtCompletion` (normal return and panic), `extensions/accesslog/lifecycle_test.go:TestRetainedRecordDoesNotChange`, `extensions/accesslog/accesslog_test.go:TestRecordLogValueOmitsSensitiveFields`, `extensions/outboundsign/outboundsign_test.go:TestWithKeyAcceptsMinimumKey`, `extensions/outboundsign/outboundsign_test.go:TestNewlineInMethodFailsClosed` (a method with a newline fails before the transport, because the core does not check method tokens), `extensions/outboundsign/outboundsign_test.go:TestWithKeyOutsideGatewayPassesThrough`, `examples/gateway/main_test.go:TestStartupFailureIsReportedSafely` (extended with signing-key cases), and the `Example` functions of both packages.
