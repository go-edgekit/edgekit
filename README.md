# Go Gateway Starter

A deliberately minimal, extensible API gateway in Go. It uses `net/http`, `httputil.ReverseProxy`, and ordinary HTTP middleware. No third-party dependencies.

## What it does

- Forwards all `/api/` requests to a configurable HTTP upstream, keeping the original path and query.
- Supports global and per-route middleware using `func(http.Handler) http.Handler`.
- Includes one standalone example extension (`extensions/headers`).
- Validates route configuration and shuts down gracefully.
- Includes integration tests with a local `httptest` upstream.

## Run it

From the project directory, start the sample upstream in one terminal:

```text
go run ./cmd/upstream
```

Start the gateway in a second terminal:

```text
go run ./cmd/gateway
```

Send a request through the gateway:

```text
curl -i 'http://localhost:8080/api/hello?q=1'
```

The response should contain `X-Gateway: starter` and JSON generated by the upstream.

Run the tests:

```text
go test ./...
```

To change the upstream or listening address, use Nushell environment variables before starting the gateway:

```nu
$env.GATEWAY_UPSTREAM = 'http://127.0.0.1:9999'
$env.GATEWAY_LISTEN_ADDR = ':8081'
go run ./cmd/gateway
```

## Extend it

Make any middleware by writing a function of type `func(http.Handler) http.Handler`.
Use `gateway.New(routes, globalMiddleware...)`, and attach route-specific middleware with `Route.Middlewares`.

This project supports **compile-time extensions**. It intentionally does not provide dynamic plugin loading, plugin registries, custom request contexts, a control plane, databases, authentication, rate limiting, or quotas yet.

## Boundaries to revisit later

- Inbound middleware wraps `http.Handler` and can reject requests before proxying.
- Upstream request rewriting belongs in the reverse proxy's `Rewrite` hook.
- Upstream response hooks can use `ReverseProxy.ModifyResponse` when there is an actual requirement.
- Outbound HTTP behavior can be customized through an `http.RoundTripper`.
- Consider adding public extension APIs for those distinct phases as concrete use cases emerge.
- Production use will require additional configuration management, security review, TLS, request size limits, appropriate timeouts, reliable telemetry, and more thorough HTTP behavior tests.

The exported API is intentionally experimental; rename the module path before publishing.
